# 「必刷题」题库维护与出题规范

> 面向维护者：本文档说明「必刷题」板块的题库结构、加题流程、难度标准与双版本解析写法。跟着做，不写代码也能加题。
> 软件层面的校验命令、构建与统计流程也一并写在这里；所有命令都在**项目根目录**执行。

## 1. 板块是什么

「必刷题」是网站上的纯刷题板块（与课程板块相互独立）：

- 入口：主导航「必刷题」或 `#/problems`；
- 只包含题目与解析功能：题库列表、筛选、刷题、判分、双版本解析、错题本、收藏、统计；
- 页面代码：`js/problems.js`（数据与进度引擎）、`js/views-problems.js`（视图）、`css/problems.css`（样式）；
- 题库数据：`content/problems/` 目录，每个科目一个 JSON 文件 + 自动生成的 `manifest.json`。

## 2. 题库结构

### 2.1 文件清单

| 文件 | 内容 |
|---|---|
| `content/problems/ds.json` | 数据结构 30 题 |
| `content/problems/co.json` | 计算机组成原理 30 题 |
| `content/problems/os.json` | 操作系统 30 题 |
| `content/problems/net.json` | 计算机网络 30 题 |
| `content/problems/pl.json` | 编程语言基础 25 题 |
| `content/problems/algo.json` | 算法与复杂度 30 题 |
| `content/problems/db.json` | 数据库 25 题 |
| `content/problems/brain.json` | 智力·场景面试 20 题 |
| `content/problems/manifest.json` | 自动生成：题目索引与统计（勿手改） |

### 2.2 科目文件格式

```json
{
  "subject": "ds",
  "name": "数据结构",
  "desc": "线性表、树、图、排序、查找等核心结构",
  "questions": [ /* 题目对象，按难度从低到高排列 */ ]
}
```

- `subject` 为固定 id（ds / co / os / net / pl / algo / db / brain），`name`、`desc` 照上表。
- `questions` 内题目**必须按难度从低到高排序**（difficulty 1 在前、3 在后）。

### 2.3 题目对象字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | 是 | `pb-<subject>-NNN`，按文件顺序从 001 连续编号（顺序 = id 顺序） |
| topic | string | 是 | 考点标签，2-16 字（如「栈与队列」「Cache」「TCP 拥塞控制」） |
| type | string | 是 | single / multi / judge / fill / short / code / complexity |
| difficulty | number | 是 | 1 = 入门，2 = 进阶，3 = 冲刺 |
| stem | string | 是 | 题干，纯文本；建议不超过 300 字 |
| options | string[] | 视类型 | 仅单选/多选：4-5 个；不带「A.」前缀；不得重复 |
| answer | 视类型 | 是 | 见 2.4 |
| pro | string | 是 | 专业版解析（100-260 字） |
| kid | string | 是 | 宝宝巴士版解析（80-200 字） |

### 2.4 题型与答案写法

| type | 含义 | 选项 | answer 写法 | 判分 |
|---|---|---|---|---|
| single | 单选题 | 4-5 个 | `"B"` 单个大写字母 | 自动 |
| multi | 多选题 | 4-5 个 | `["A","C"]` ≥2 个不重复字母 | 全对才算对 |
| judge | 判断题 | 无 | `true` / `false`（布尔值） | 自动 |
| fill | 填空题（单空） | 无 | `["答案","可接受变体"]` | 归一化匹配（忽略大小写与首尾空格） |
| short | 简答题 | 无 | 参考答案全文（字符串，≥30 字） | 自评 |
| code | 代码/算法题 | 无 | 参考实现 + 复杂度说明，注明语言，代码用 `\n` 换行 | 自评 |
| complexity | 复杂度分析 | 无 | 结论 + 简要推导 | 自评 |

约定：填空题题干用 `____` 显式留空；多选题题干标注「（多选）」；选择题不用「以上都对/都错」类选项。

## 3. 新增一道题的完整流程

1. **定题**：选一个经典考点（408 考研 / 计算机面试），用自己的话组织题干，先想清楚正确答案与依据；
2. **判定难度**：按第 4 节标准给出 difficulty（1/2/3）；
3. **写入文件**：打开对应科目的 `content/problems/<subject>.json`，按**难度顺序**插入题目对象；
   - id 编号必须与文件顺序一致：插在第 12 位就是 `pb-xx-012`，并把其后所有题的 id 依次顺延（可用编辑器批量替换，或参考第 7 节脚本思路校验）；
   - 保持 JSON 合法：UTF-8 编码、无 BOM、字符串内换行写 `\n`；
4. **写双版本解析**：按第 5 节规范写 `pro` 与 `kid`；
5. **校验**：`node tools/validate-problems.js --file content/problems/<subject>.json`，必须 PASS；
6. **更新索引**：`node tools/build.js`（会刷新 `content/problems/manifest.json` 与全站统计）；
7. **本地预览**：（可选）`node server/server.js` 后打开 `http://127.0.0.1:8642/#/problems` 检查渲染；
8. **提交**：变更 `content/problems/` 与 `content/stats.json` 一起提交即可；CI 会再次运行题库校验。

增删题目时请同步调整该科目在任务书中的目标题量；全库总量只增不减（目前 220 题）。

## 4. 难度评定标准

| 档位 | difficulty | 特征 | 例子 |
|---|---|---|---|
| 入门 | 1 | 单一知识点直接回忆或一步计算 | 补码范围、栈的特点、简单复杂度判断 |
| 进阶 | 2 | 2-3 个知识点综合，或典型计算/推导；408 常规题、面试中频题 | Cache 命中率计算、子网划分、信号量 PV |
| 冲刺 | 3 | 易错陷阱、多步推导、经典高频难题 | 流水线冒险计算、TCP 拥塞窗口全程、银行家算法、复杂 DP、系统设计场景 |

每个科目的三个档位都必须有题；新增题注意别让某档过空。

## 5. 双版本解析写作规范

### 5.1 专业版（pro）

- 术语准确；先给结论再给依据；
- 包含推导或对比：为什么是这个答案、其他选项错在哪；
- 结尾用「易错点：……」点出常见踩坑；
- 正文 100-260 字（校验下限 80 字，去空白）。

### 5.2 宝宝巴士版（kid）

- 口语化、零基础能懂：用生活类比（排队、图书馆、快递、厨房、停车场……）解释同一个知识点；
- 不堆术语；必须出现的术语先打比方再轻轻点名；
- **结论与专业版完全一致、答案是同一个**；
- 正文 80-200 字（校验下限 60 字，去空白）。

### 5.3 好例速览

> 专业版：「……平均移动次数 = [n + (n-1) + … + 1 + 0] / (n+1) = n/2。易错点：不要与删除操作混淆——删除平均移动 (n-1)/2 个元素。」
> 宝宝巴士版：「想象你在食堂排长队，想插队进去：插在队尾谁都不用挪，插在队首所有人都要后退一步。n 个人平均下来，大约要挪一半人……」

两版都禁止：敷衍词（“略”“显然”）、过度卖萌、表情符号、与题干无信息增量的重复。

## 6. 文案禁区（校验会直接判 FAIL）

1. 不出现 emoji 或图形符号（含 ✅ ⚠️ ★ 等）；
2. 不出现外部链接（http / https）；
3. 不出现 HTML 标签；
4. 不出现「TODO / 待补充 / Lorem ipsum」等占位符；
5. 不复制商业题库、教材、博客原文（改写必须用自己的表述）；
6. 选项不使用「以上都对 / 以上都错」类取巧表述；
7. 全库题干指纹去重：题目不得与其他题重复或高度近似。

## 7. 校验与统计命令

```bash
# 单科自查（写作时用，随写随查）
node tools/validate-problems.js --file content/problems/ds.json

# 全库校验 + 分布矩阵 + 去重核验（提交前、CI 都会跑）
node tools/validate-problems.js

# 输出统计报告 JSON（可选，供文档引用）
node tools/validate-problems.js --json docs/problems-report.json

# 重新生成题目索引与全站统计（增删题后必须执行）
node tools/build.js
```

校验内容：字段完整性、id 与排序、答案与选项合法性、双版本解析字数与禁用词、题量（每科精确数）、三档难度分布、题型分布、全库去重。

常见 FAIL 与处理：

| 报错 | 处理 |
|---|---|
| `id 与文件顺序不一致` | 按位置重新编号（第 N 位 = `pb-xx-0NN`） |
| `文件内难度应从低到高排序` | 调整题目顺序 |
| `pro 太短 / kid 太短` | 按第 5 节补足解析 |
| `包含 emoji / 外部 URL / HTML 标签` | 删除对应字符或改为纯文本 |
| `题干重复` | 换一种问法或换考点 |
| `题量应为 N，当前 M` | 增删到目标题量 |

## 8. 数据与统计说明

- 题目索引 `content/problems/manifest.json` 由构建脚本生成（含全部题目的 id / 科目 / 考点 / 题型 / 难度 / 题干），**不要手动编辑**；页面加载的就是这份索引，全量题目按科目懒加载。
- 做题记录、错题与收藏保存在用户浏览器本地（localStorage 键 `cslearn.problems.v1`），与课程学习记录分离；统计页支持导出 JSON / CSV 与清空。
- 题库不做付费墙；主观题不自动判分，只提供参考答案与自评入口。
